# Ayvago: build a platform slice

A slice is one shippable change listed in `docs/plan/phase-N.md`. The owner writes in Turkish; you
reply in Turkish, but **everything committed is English**.

## 0. Where things live

| Need | Place |
|---|---|
| Route / page | `apps/web/app/[locale]/…` (server components; `setRequestLocale`, `generateMetadata`, `localizedAlternates`) |
| Client UI | `apps/web/components/<area>/` + a CSS module; read **semantic tokens only** (`var(--surface)`, `--accent`, `--text-muted`…) |
| Logic | `apps/web/lib/<area>/` as pure, unit-tested functions; Firebase access only through `lib/firebase/client.ts` loaders (`loadAuth`, `loadFirestore`, `loadFunctions`, `loadDatabase`) |
| Text | `apps/web/messages/en.json` first, then `tr.json` with the same keys (the message test fails otherwise). Correct Turkish: ç ğ ı İ ö ş ü |
| Catalog | `lib/catalog` over `packages/shared` (`seed-catalog.ts`; `arcade-catalog.ts` is **generated by the studio and synced by a workflow, never edited here**) |
| Game protocol | `packages/platform-adapter` (the original) and `apps/web/lib/gha/bridge.ts`; games run in a sandboxed iframe and only exchange `GHA_*` messages |
| Themes | `packages/themes` (`tokens.ts`; the contrast test must pass) |
| Firestore / RTDB / Storage rules | `firebase/*.rules*`, tests in `firebase/tests` (start from deny-all) |
| Cloud Functions | `firebase/functions/src` (europe-west1, `onCall` / `onSchedule`, logic in its own module so tests can import it) |
| Server routes | `apps/web/app/api/**/route.ts`; secrets only from server env vars (never `NEXT_PUBLIC_`) |

## 1. Plan the slice
1. Read the relevant spec in `docs/specs/` and the roadmap section. If the slice changes a
   decision, write an ADR (`docs/adr/00NN-*.md`) in the same change.
2. Add the slice row to the phase table in `docs/plan/phase-N.md` (status 🚧).

## 2. Build
- Every user-visible string is a message key in both locales. No text in code.
- Pages that hold private or short-lived content are `noindex`.
- Mobile first: check 360 px wide, the phone bottom bar and safe areas. All four themes
  (arcade default, minimal light/dark, retro, cartoon) must look right.
- Rules: a rule change ships with emulator tests for both the allowed and the refused paths.
- Functions: validate input, check `request.auth`, rate-limit where a player could loop, and log
  with `logger`.
- Never commit secrets; owner-only values go into the setup doc as ⏳ steps.

## 3. Check (all must pass before you report)
```bash
pnpm format            # then pnpm format:check
pnpm typecheck
pnpm test              # web, shared, themes, adapter, firebase (emulators)
pnpm --filter @ayvago/web build
```
- The Firebase emulators need the proxy variables removed:
  `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy pnpm --filter @ayvago/firebase test`.
- For UI, run `next start` (or `next dev` with `NEXT_PUBLIC_FIREBASE_EMULATORS=1`) and look at
  Playwright screenshots on desktop and a phone profile. To play local game builds, set
  `AYVAGO_DEV_ARCADE_ORIGIN=http://localhost:<port>` (a `vite preview` of ayvago-games).
  The platform must run on `http://localhost:3000`, the only local origin the games trust.

## 4. Document (same change, owner request)
- `docs/plan/phase-N.md`: the slice section — what shipped, deviations, tests, still open.
- `docs/setup/phase-N.md`: every owner step (⏳), or "nothing to set up".
- Roadmap §12 checklist and the §2.4 functions table; the affected spec's implementation status;
  the README phase table.

## 5. Ship
- Branch from `main`, commit in English, push, open a PR whose body lists what changed, tests,
  and owner steps. Watch CI until it is green.
- If the slice needs a new game build, it goes to selchook/ayvago-games first; its catalog
  reaches this repo through the "Sync arcade catalog" PR.
